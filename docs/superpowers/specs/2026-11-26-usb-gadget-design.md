# 本机 USB 口直连：虚拟光驱、虚拟 U 盘、gadget 键鼠

2026-11-26

## 目标

宿主机是带 USB 设备口的 ARM 板（目标硬件：RK3566 / RK3588 一类，dwc3 OTG 口）时，
用一根 USB 线把板子的设备口接到被控机，被控机就能看到：

- 一个**光驱**，可以挂 ISO：装系统、从光盘启动；
- 一个**U 盘**，可以挂 `.img`：拷驱动、救援盘；
- 一套**键盘和鼠标**，可以代替 CH9329。

宿主机不满足条件时，这个功能不出现；ARM 板上条件不全时，页面说明缺了什么。

成功判据：

- RK 板上被控机能认出光驱和 U 盘，BIOS 里能从挂上的 ISO 启动；
- 串口选「本机 USB 口直连」后，控制页键鼠可用，包括 BIOS 里的键盘，控制页的
  键盘指示灯也照常工作；
- 挂盘、换盘、弹盘都不会让键盘掉线；
- x86 宿主机上什么都不变：没有新界面，接口回「不支持」。

## 非目标

- 媒体键、自定义 HID（CH9329 的 `0x03`、`0x06`，`ch9329.js` 没用到）。
- Android 宿主机：要 root，而且各家内核的 gadget 支持不一。
- 从网址下载镜像、新建空白 U 盘。
- 挂载状态跨重启保留：重启后两个槽都是空的，免得开机时意外把盘插到被控机上。

## 已探明的前提

| 事实 | 影响 |
| --- | --- |
| 开发机是 x86_64，没有 `/sys/class/udc` | 真机验证只能在 RK 板上做；自动测试对着临时目录跑 |
| 服务以普通用户运行（`systemd.rs` 里的 `User=`） | 建 gadget 要 root，见「权限」 |
| CH9329 协议全在浏览器 `ch9329.js` 里，服务端 `serial_bridge.rs` 只透传字节 | 服务端模拟一颗 CH9329，客户端不用改 |
| `ch9329.js` 实际发的命令：`0x01` `0x02` `0x04` `0x05` `0x08` `0x09` `0x0C` `0x0F` | 模拟器只需覆盖这几条 |
| CH9329 绝对鼠标坐标是 0–4095，键盘数据就是 8 字节标准键盘报告 | HID 描述符照这个定，不用换算 |
| f_mass_storage 的 `cdrom`、`ro` 只能在没挂文件时改 | 光驱和 U 盘做成两个固定的逻辑盘，`cdrom` 建好后不再改 |

RK 板的 OTG 口在很多发行版镜像里默认是主机模式（`dr_mode = "host"`），要在设备树
里改成 `peripheral` 或 `otg`，`/sys/class/udc` 下才会出现控制器。这一条写进 README
和不可用时的提示。

## 启用判断

四条同时满足才可用，否则返回第一条不满足的原因：

1. `std::env::consts::ARCH` 是 `aarch64` 或 `arm`。不满足时整个功能隐藏，不提示；
2. `/sys/kernel/config/usb_gadget` 存在（configfs 已挂载，且 `libcomposite` 已加载）；
3. `/sys/class/udc` 下至少有一个控制器；
4. root 准备那一步已经跑过，gadget 目录在、文件归服务用户。

判断结果在启动时算一次，然后缓存。`GET /api/usb` 同时返回结果和原因。

## 权限

在 systemd 单元里加一行 `ExecStartPre=+<exe> usb-gadget-setup`（`+` 表示这一步以 root
执行），只在 ARM 上写进单元文件。这个子命令：

1. `modprobe libcomposite`，失败不算错，可能是编译进内核的；
2. 不满足第 1–3 条就直接退出 0，不让服务启动失败；
3. 在 `/sys/kernel/config/usb_gadget/rust-kvm` 下建 gadget（结构见下）。已经存在
   就先解绑再重建，保证每次启动都是干净的状态；
4. 把服务运行时要写的文件 chown 给服务用户：两个逻辑盘的 `file`、`ro`、
   `forced_eject`，gadget 的 `UDC`，以及 `/dev/hidg0`–`/dev/hidg2`；
5. 绑定第一个控制器。

服务本身仍是普通用户，只写上面那几个文件。挂盘时由内核用写入者的身份打开镜像，
镜像目录本来就归服务用户，读写没有问题。

## Gadget 结构

一个 gadget、一个配置，四个功能：

| 功能 | 用途 | 要点 |
| --- | --- | --- |
| `hid.kbd` → `/dev/hidg0` | 键盘 | 开机协议（subclass 1, protocol 1），8 字节输入报告，1 字节键盘灯输出报告 |
| `hid.abs` → `/dev/hidg1` | 绝对鼠标 | 数位板形式，X/Y 逻辑范围 0–4095，3 键加滚轮 |
| `hid.rel` → `/dev/hidg2` | 相对鼠标 | 开机协议鼠标（subclass 1, protocol 2），3 键、dx/dy、滚轮 |
| `mass_storage.0` | 存储 | `lun.0` 是光驱（`cdrom=1` `ro=1` `removable=1`），`lun.1` 是 U 盘（`removable=1`） |

- **USB 标识**：VID `0x1d6b`，PID `0x0104`（Linux Foundation 的 Multifunction
  Composite Gadget）。厂商写 `rust-kvm`，产品名写 `Virtual KVM`，序列号取板子的
  machine-id 前 16 位。
- **一直插着**：服务启动时就绑定控制器，被控机一直能看到这个设备。代价是被控机上
  一直有一个空光驱和一个「无介质」的可移动盘，跟插着读卡器差不多（已和用户确认）。
- **挂盘、换盘、弹盘只动对应逻辑盘的文件**，不解绑、不重新枚举，键盘不会掉线。
- **hidg 的 hidg0–2 编号**按功能建立的顺序分配。setup 按上表顺序建立，运行时再从
  `hid.*/dev` 读主次设备号核对，对不上就报不可用，不去猜。

## 模块划分

| 模块 | 职责 | 依赖 |
| --- | --- | --- |
| `src/usb_gadget.rs` | 启用判断；setup 子命令建 gadget；运行时挂盘、弹盘、查状态。configfs 根目录和 udc 目录都作为参数传进来，测试时换成临时目录 | 只有文件系统 |
| `src/hid_emulator.rs` | 纯逻辑：输入 CH9329 字节流，输出「写哪个 hidg、写什么」和「回什么应答」。不碰文件 | 无 |
| `src/serial_bridge.rs` | 新增一个假端口 `usb-gadget`。打开它时不开串口，改成把字节交给模拟器，模拟器的输出写进 `/dev/hidg*` | 上面两个 |
| `src/media.rs` | 镜像目录：列出、上传、删除，文件名校验 | 只有文件系统 |
| `src/main.rs` | 新路由 | 上面这些 |

### 模拟器（`hid_emulator.rs`）

- **组帧**：按 `57 AB addr cmd len data sum` 解析，校验错就丢掉，回
  `cmd | 0xC0` 加错误码 `0xE3`（校验错），跟真芯片一样。
- **地址**：`ch9329.js` 发的地址是 `0x00`。地址不是 `0x00` 也照常处理，不去模拟
  多芯片寻址。

| 命令 | 处理 | 应答 |
| --- | --- | --- |
| `0x01` 查信息 | 版本固定 `0x30`；USB 状态读 udc 的 `state`，`configured` 回 `0x01`，否则 `0x00`；键盘灯取最近一次读到的输出报告；`suspended` 时第 4 字节回 `0x03` | `0x81` 加 8 字节 |
| `0x02` 键盘 | 8 字节原样写 `hidg0` | `0x82 00` |
| `0x04` 绝对鼠标 | 首字节 `0x02` 后面是按键、X、Y（小端）和滚轮，按描述符重排后写 `hidg1` | `0x84 00` |
| `0x05` 相对鼠标 | 首字节 `0x01` 后面是按键、dx、dy 和滚轮，写 `hidg2` | `0x85 00` |
| `0x08` 读参数配置 | 回一份固定的 50 字节配置，波特率字段填 `9600`，跟出厂值一样 | `0x88` 加 50 字节 |
| `0x09` 写参数配置、`0x0C` 恢复出厂、`0x0F` 复位 | 什么也不做 | 成功 |
| 其他 | 不处理 | `cmd | 0xC0`，错误码 `0xE1`（命令码错） |

- **写失败**：被控机没接或没枚举时，hidg 会返回 `EAGAIN` 或 `ESHUTDOWN`。照样回
  成功应答，但这一帧丢掉。这跟 CH9329 没接被控机时的行为一样，查信息时 USB 状态
  会如实回 `0x00`，控制页能看出来。
- **键盘灯**：读 `hidg0` 拿输出报告，由一个专门的线程阻塞读，读到就更新键盘灯状态。
- **断线松键**：串口桥现有的 `RELEASE_FRAMES` 照样经过模拟器，不用特殊处理。
- **设置页**：串口选 `usb-gadget` 时，隐藏读芯片、改波特率、改工作模式、恢复出厂
  这几个按钮。波特率下拉框也隐藏，因为这个端口没有波特率。

### 串口列表

`/api/serial/ports` 在 gadget 可用时，列表最前面加一项：
`{name: "usb-gadget", description: "本机 USB 口直连（不需要 CH9329）"}`。配置里存的就是
`serial.port = "usb-gadget"`，切换机器配置、安卓客户端都不用改。

## 镜像目录（`media.rs`）

- **位置**：新配置项 `usb.imageDir`，默认是工作目录下的 `images/`，不存在就建。
- **列表**：只列 `.iso` 和 `.img`，返回名字和大小。忽略 `.part`。
- **文件名**：只允许一层普通文件名，不能带 `/`、`\`、`..`，也不能以 `.` 开头；
  扩展名必须是 `.iso` 或 `.img`。不合法的名字一律回 400。
- **上传**：`PUT /api/usb/images/<名字>`，请求体流式写进 `<名字>.part`，写完 fsync，
  再改名成正式名字。这个路由不受请求体大小限制。同名文件正在挂着时拒绝（409），
  没挂着就覆盖。连接中途断开时删掉 `.part`。
- **进度**：上传进度由浏览器用 `XMLHttpRequest.upload.onprogress` 显示，服务端不管。
- **删除**：`DELETE /api/usb/images/<名字>`，正在挂着时拒绝（409）。
- **手动放入**：自己 scp 进去的文件，刷新列表就能看到。

## 挂盘接口

- `GET /api/usb`：返回 `{available, reason, slots: {cdrom, disk}, images}`。每个槽是
  `{image, readOnly}`，空槽的 `image` 为 `null`；`images` 是镜像列表。
- `POST /api/usb/cdrom/mount`，参数 `{image}`：只接受 `.iso`。
- `POST /api/usb/disk/mount`，参数 `{image, readOnly}`：`.iso` 和 `.img` 都接受。
- **挂盘步骤**：先往 `forced_eject` 写 1，把这个槽清空；U 盘再写 `ro`；最后往
  `file` 写镜像的绝对路径。
- `POST /api/usb/{cdrom|disk}/eject`：往 `forced_eject` 写 1。
- **同一个镜像**不能同时挂在两个槽上，回 409。
- **状态以 configfs 为准**：每次查询都读 `file` 的内容，不在内存里另存一份，免得被控机
  自己弹出光盘后两边对不上。

## 界面

控制页工具栏加一个「虚拟介质」按钮和面板，形式跟现在切换机器配置的面板一样，只在
`available` 时显示。面板内容：

- **光驱一行**：ISO 下拉框，挂载和弹出按钮，显示当前挂的盘。
- **U 盘一行**：镜像下拉框、「只读」勾选框，挂载和弹出按钮。
- **镜像列表**：名字、大小、删除按钮；一个上传按钮，上传时显示进度条。

设置页的串口下拉框里会出现「本机 USB 口直连」。ARM 上 gadget 不可用时，在串口那一节
用一行提示写出原因。

## 测试

- **`hid_emulator.rs`**：喂 CH9329 帧，检查写出的 HID 报告和回出的应答字节。用例覆盖
  每条命令、校验错、半帧和粘包、未知命令、键盘灯更新后查信息。
- **`usb_gadget.rs`**：对着临时目录跑。检查 setup 建出的目录和属性值，挂盘、弹盘
  写了哪些文件、按什么顺序写；x86 下判定为不可用；缺 udc 时给出正确的原因。
- **`media.rs`**：文件名校验，包括 `../x.iso`、`a/b.iso`、`.hidden.iso`、`x.exe`；
  上传成功后改名；中断时 `.part` 被删掉；正在挂着的镜像不能删、不能覆盖。
- **网页**：串口选直连时芯片按钮隐藏，虚拟介质面板的状态渲染。都写成跟现有
  `tests/web/*.test.js` 一样的纯函数测试。
- **真机（RK 板）**：被控机认出光驱和 U 盘；BIOS 从 ISO 启动；直连键鼠在 BIOS 和系统
  里都能用；键盘指示灯跟着变；挂盘、换盘不让键盘掉线；拔掉线后控制页显示 USB 未连接。

## 实施顺序

1. `hid_emulator.rs`：纯逻辑，可以先在 x86 上写完测完；
2. `usb_gadget.rs` 的 setup 和启用判断，以及 systemd 单元的改动；
3. 串口桥接上模拟器，设置页隐藏芯片按钮。到这一步就能在 RK 板上验证键鼠；
4. `media.rs` 和挂盘接口；
5. 控制页「虚拟介质」面板；
6. README：硬件要求、设备树、接线、权限说明。
