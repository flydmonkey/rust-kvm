## 手工验收步骤（建议顺序）

1. **连接与 TOFU：** 输入 `192.168.x.x` 或完整 URL → 首次弹出指纹对话框 → 信任并进入控制页 → 断开重连无二次提示 → 修改宿主机证书后应提示指纹变更。
2. **视频：** 默认 MJPEG 有画面；设置改为 H.264 保存并返回 → 画面仍正常；切回 MJPEG。
   - MJPEG 1080p30 连看 5 分钟，在被控端开一个秒表：操作到画面的延迟不应越拖越大，App 内存不应持续上涨。
   - H.264 下快速拖动窗口：不应出现持续花屏；若出现，应在约 1 秒内恢复（logcat 里 `VideoPipeline` 会打 `Reopening video stream`）。
   - H.264 下把分辨率改成 1280×720：画面应在几秒内恢复，不黑屏。
   - 若本机解码器吃不下这路 H.264（连续 3 次解码失败且没出过一帧），底部提示「本机 H.264 解码反复失败，可在设置里把编码改成 MJPEG」；出画面后提示消失。
   - 宿主机关闭音频时底部提示「音频不可用」，画面和键鼠不受影响。
   - 若宿主机 H.264 编码器起不来，服务端会退回 MJPEG：画面正常，底部显示「H.264 不可用，已退回 MJPEG：原因」。
   - 控制页全屏（状态栏、导航栏隐藏，从边缘划出后自动收回）；放着不动屏幕不熄灭；横竖屏切换、插拔外接键盘都不应断线重连；刘海屏上画面不被挡。
3. **音频：** 有声音；点静音立刻无声（不再拖一小段尾音）；取消静音恢复，且不会先冒出一段旧声音。连听 5 分钟，声音与画面的错位不应越来越大。
4. **输入：** 触摸点击/拖拽；切换绝对/相对鼠标；软键盘输入字符。
   - 绝对模式：点桌面图标落点准确（MJPEG 与 H.264 各点一次四个角附近）；拖动窗口标题栏；长按出右键菜单，且长按前没有误触左键。
   - 双指上下划动网页能滚动，方向和手机上一致；双指轻点出右键菜单。
   - 相对模式：单指划动只挪光标、不会拖出选区；轻点是左键单击。
   - 点「键盘」呼出软键盘：连续输入字母、数字、符号不重复不丢；退格、回车可用；中文等非 US 键盘字符会被跳过。
   - 软键盘弹出时画面缩到键盘上方，键盘上方出现功能键栏（Ctrl/Alt/Shift/Win、Esc、Tab、方向键、Home/End/PgUp/PgDn/Del、F1–F12）：点 Ctrl 再在软键盘打 `c` 应为复制；Ctrl 点亮后点 Alt 再点 Del 是 Ctrl+Alt+Del；连点两下 Win 打开开始菜单；修饰键用一次后自动熄灭；收起软键盘时已点亮的修饰键也会熄灭。
5. **工具栏：** 粘贴剪贴板文本；Ctrl+Alt+Del；松开所有键（键卡住时尤其验证）。
   - **快捷键面板：** 点 Win+L 被控端锁屏；Win+R 后再点自定义的 `Win+R Enter` 类多步能连续生效；加一条无效的（如 `Ctrl+Foo`）应提示「不认识的按键「Foo」」；自定义重启 App 后仍在、可删除。打开「开机连按」后点 Del 再重启被控端，应进 BIOS；底部显示已按次数，点「停止连按」或任一快捷键即停；连按中外接键盘按键不转发。
6. **接管：** 浏览器或第二客户端占用串口 → 本端提示 busy → 点接管后键鼠恢复。
7. **设置：** 修改分辨率/fps/codec、音频窄带、串口端口等 → 保存 → 返回控制页确认生效。
   - 控制页按一次返回（或边缘返回手势）只提示「再按一次返回断开连接」，2 秒内再按一次才回到连接页；软键盘弹出时第一次返回只收起键盘。
   - 连接失败（如串口被占用后点取消）时点「断开」能回到连接页。
   - 连接页点最近服务器直接发起连接。
8. **重连：** 控制页开启时关闭手机 Wi-Fi 数秒再打开 → 出现「重连中」→ 画面与键鼠恢复；确认未自动 takeover。

## 已知限制（一期不做）

- 无 mDNS / 局域网自动发现（仅手动地址 + 最近 8 条）
- 无录制、无统计 HUD 叠加层
- 无 Keyboard Lock 级系统键全捕获
- 无 CH9329 芯片波特率/工作模式配置 UI
- 无鉴权（与 Windows 服务一致，假定可信局域网或 VPN）
- CH9329 ACK 队列为一期简化版（写后不严格等 ACK）；若特定硬件依赖 ACK 需后续收紧

## 二期 2a：本机作为宿主机（键鼠）真机验收

准备：一部 Android 8.0+ 手机作宿主机（OTG 线接 CH9329，CH9329 另一端接目标电脑），另一台设备作客户端（浏览器或装了本 App 的手机），两者同一局域网。

1. **授权与启动：** 连接页点「本机作为宿主机」→ USB 设备列表出现串口芯片 → 点「授权」并允许 → 点「启动宿主机」→ 显示「运行中」、`https://<IP>:8443` 和证书指纹，状态栏有常驻通知。
2. **浏览器客户端：** 另一台电脑浏览器打开该地址 → 证书警告页核对指纹后继续 → 页面加载（与 Windows 版同一套前端）→ 点键鼠图标连接串口 → 在目标电脑上打字、移动鼠标、点击都正常；视频区域无画面属于预期。
3. **Android 客户端：** 另一部手机用本 App 连接该地址 → TOFU 指纹与宿主机页面显示的一致 → 控制页键盘、触摸鼠标、粘贴可用。
4. **占用与接管：** 浏览器已占用串口时用 App 连接 → 提示「串口正被另一个控制端占用」；选择接管 → 浏览器端收到「控制权已被另一个客户端接管」；接管期间按住的键在目标机上不会卡住。
5. **后台与停止：** 宿主机锁屏 5 分钟后客户端仍能操作；拔掉 OTG 线 → 客户端提示「串口连接已中断」；点通知里的「停止」→ 服务停止，客户端断开。

## 二期 2b：采集卡画面真机验收

准备：在 2a 的基础上，用带外接供电的 OTG Hub 同时接 HDMI 采集卡（UVC MJPEG，MS2109 一类）和 CH9329，目标电脑的 HDMI 接到采集卡。

1. **授权：** 宿主机页面「USB 采集卡」一栏出现采集卡 → 点「授权」→ 先弹相机权限、允许后再弹 USB 授权 → 显示「已授权」。拒绝相机权限时页面给出到系统设置打开的提示。
2. **出画面：** 浏览器打开宿主机地址 → 看到目标机画面，鼠标键盘照常可用；Android 客户端连接同样出画面。`/api/video/stats` 里 `capturing=true`、`fps` 接近设置值、`resolution` 是实际分辨率。
3. **静止不耗流量：** 目标机画面静止时 `sentMbps` 接近 0，页面不显示卡住。
4. **改设置：** 设置页把分辨率改成 1280×720（或改 fps）→ 保存 → 画面不断开地切到新格式；选 H.264 时画面照常、并提示「Android 宿主机还不支持 H.264」。
5. **按需启停：** 关掉所有客户端约 3 秒后 stats 显示 `capturing=false`；刷新页面不会让画面黑一秒以上。
6. **拔插：** 拔掉采集卡 → stats 的 `error` 说明原因、键鼠不受影响；插回、重新授权后画面自动恢复。

已在 JVM 上自动化覆盖（不需要真机）：UVC 描述符解析（MS2109 形状，含 YUY2 干扰和音频接口）、格式与 alt setting 选择、probe 编解码、负载拼帧（EOF / FID 翻转 / 错误帧丢弃）、采集按需启停与重开、`/ws/video` 推流协议。真机上才能验证的是等时传输 JNI、具体采集卡的 probe/commit 兼容性和 OTG 供电。
